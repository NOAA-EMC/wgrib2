◆ f_set_ftime2()

int f_set_ftime2 ( ARG1  )

Set forecast time in GRIB sections.

(same as -set_ftime).

The wgrib2 inventory has a fragment that looks like 

 :d=2014122500:12 hour fcst:vt=2014122512
  • d=2014122500 is the Reference time, usually the analysis or start of the forecast time.
  • 12 hour fcst is the "ftime", the time is 12 hours after the reference time
  • vt=2014122512 is the verification time (ref time + 12 hours)

Wgrib2 has options to change the forecast time (ftime). The -set_ftime2 option is easier to use and will change the Product Definition Templates as needed. For compatibility, -set_ftime1 is still available. However, -set_ftime1 should not be used as will be eventually removed.

This routine is also called by the -set_ftime option.

-set_ftime2 FTIME

This is the same as: -set_ftime FTIME

The allowed formats of FTIME are the same as ftimes from a wgrib2 inventory.

Original: :d=2014113018:6 hour fcst: options: -set_date 2014122500 -set_ftime "12 hour fcst" New: :d=2014122500:12 hour fcst:

Original: :d=2014113018:6 hour fcst: options: -set_date 2014122500 -set_ftime "0-6 hour ave fcst" New: :d=2014122500:0-6 hour ave fcst:

Original: :d=2014113018:6 hour fcst: options: -set_date 2014122500 -set_ftime "124@6 hour ave(0-6 hour ave fcst),missing=0" New: :d=2014122500:124@6 hour ave(0-6 hour ave fcst),missing=0:

After changing the time stamp, you can save the file with -grib NEW.grb

Parameters
ARG1List of function arguments set by wgrib2's main() function (see ARG1). These arguments won't be relevant to the average wgrib2 user. See the Usage section above for details about any input parameters.
Returns
0 for success. Throws fatal_error() on failure.
