20 /*
21  * ens_qc
22  *
23  * v1.0 process ensemble for mean, spread, min, max and scaled extremes
24  * which wgrib2 defines as max((max-mean), abs(min-mean)) / spread
25  * other people can define it differently.
26  *
27  * If you want mean and spread, this is rooutine is faster than
28  * -ens_processing because that routine sorts the data.
29  *
30  * This routine was written because an ensemble data assimilation had one member
31  * that had ozone many orders of magnitude larger than expected. The reqults
32  * were not reproducable, and not seen in sixty years of data assimilation.
33  * So it must have been a glitch in one of the nodes. So this routine was
34  * written to scan for ensemble members that were N times greater than spread.
35  *
36  * Output:
37  * arg1: grib2 of ensemble min, max, mean and spread
38  * arg2: grib2 of scaled extreme value, max((max-mean), (mean-min)) / spread
39  * saved in 8 bit precision
40  * arg3: text file with the maximum value on the grid of the scaled extremee value
41  *
42  * Note: arg2 is stored in grib2 with EXTREME_FORECAST_INDEX
43  * EXTREME_FORECAST_INDEX is a local NCEP definition, so the scaled extremes will
44  * only bw written in grib format if the center is NCEP.
45  *
46  * Input:
47  * arg4: N for future use, such as different types of QC
48  * 1 is the only currently supported value
49  *
50  * Note: Code saves each grid before doing the QC code. This is not needed for the
51  * current code. However, future versions of the QC code may want access to the
52  * individual grids.
53  *
54  * 12/2021: Public Domain: Wesley Ebisuzaki
55  * 1/2020: Initial public release
56  * 9/2023: faster by using SIMD
57  * 9/2025: fix race condition: could not observe race condition in multiple attempts
58  * found by code examination, vulnerability may have been reduced
59  * by code optimizer.
60  */
