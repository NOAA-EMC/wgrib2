◆ f_number_of_coordinate_values_after_template()

int f_number_of_coordinate_values_after_template ( ARG0  )

Prints the number of values (4 byte) in the "optional list of coordinate values".

-number_of_coordinate_values_after_template

Prints section 4, octets 6-7 as an unsigned integer. It is expected that each value uses 4 octets of storage at the end of Section 4.

Parameters
ARG0List of function arguments set by wgrib2's main() function (see ARG0). These arguments won't be relevant to the average wgrib2 user. See the Usage section above for details about any input parameters.
Returns
0 for success, error code otherwise.
Note
Vertical coordinates can be easy like "400 hPa", "2 meters above ground" or "sigma=0.4". However, the situation is more complicated with the vertical coordinates in the models. In these model coordinates, the vertical are usually an integer. You need some extra information to locate the level in physical space. This information is stored in the PDT (section 4) as the "optional list of coordinate values" at the end of the product definition template.
The WMO documentation only specifies the hybrid coordinate values should be in pairs of IEEE single precision floats.

◆ f_pds_fcst_time()

int f_pds_fcst_time ( ARG0  )

Prints out the value of the forecast time.

Most grib messages include a forecast time which is stored in the Product Definition Templates (PDT). When the PDT has a forecast time, it stores the number as a 4 byte integer and the units in Code Table 4.4. For example, a 12 hour forecast could be stored with the number 12 and the units of 1 which corresponds hour. Note that the same forecast time can be stored in several ways. For example, 12 hours can be stored as:

  • value=720 , units = 0 (minutes)
  • value=12 , units = 1 (hours)
  • value=4 , units = 10 (3-hours)
  • value=2 , units = 11 (6-hours)
  • value=1 , units = 12 (12-hours)
  • value=43299, units = 13 (seconds)

The unusual 3-hour, 6-hour and 12-hour time units are a legacy of the grib version 1 standard. Note that the value is a signed integer because the grib standard allows negative forecast hours which can make sense in data assimilation.

ARG0List of function arguments set by wgrib2's main() function (see ARG0). These arguments won't be relevant to the average wgrib2 user. See the Usage section above for details about any input parameters.
Returns
0 for success, error code otherwise.
